Quick start

DevVM Cleanup cleans a development VM before a copy is handed over: sign out everywhere and leave no credentials, tokens or traces of the person who set it up. The Windows account itself (password, sign-in) is never changed.

  1. Start the program as administrator (Windows asks). Start it with the account the developers will keep using.
  2. 1. Checks must be green (VM, administrator, correct profile).
  3. Click Analyze: each module shows “found: …”. Nothing is deleted.
  4. Tick the modules/categories you want, click Clean selected … and confirm. Affected programs are closed first (after asking).
  5. The verification run starts automatically and must report “clean”.
  6. Optional: secret scan (report only), then change the computer name, run Sysprep or shut down.

1. Checks

  • Virtual machine: manufacturer/model according to WMI (Hyper-V, VMware, VirtualBox, KVM/QEMU, Xen, Parallels). On a physical PC cleaning is blocked; only the deliberately set option “not a VM – continue anyway” overrides this.
  • Administrator rights: required because registry and profile data of all programs are cleaned.
  • Profile of the signed-in user: the program must run in the profile of the user who is signed in at the PC. If it runs under another administrator account, the wrong profile would be cleaned – cleaning is blocked then.

2. Affected programs

Each module lists the programs that lock its data (e.g. Edge, Chrome, Firefox, Outlook, Teams, OneDrive). Running programs – including background processes such as Edge Startup Boost – are shown. Close programs … ends them after confirmation (politely first, then forcefully). Unsaved data is lost.

3. Analysis and selection

The analysis is a pure preview and deletes nothing. Example: Edge / Profile 1: signed in as alice@example.com; 37 passwords; cookies from 112 sites. Categories without findings cannot be selected. All browser profiles are listed individually.

Module Office / Microsoft 365

Office identities, license tokens, Outlook profiles and cache, unlink OneDrive (synced files stay as normal local files), Teams cache.

Module Browser

Edge, Chrome, Brave, Vivaldi, Opera, Firefox – all profiles. Selectable individually: sync sign-in, passwords/passkeys, cookies/sessions, site storage, autofill, sessions/tabs, history, download list, cache, password-manager extension data and optionally bookmarks. Extensions and general settings are kept.

Module Windows accounts

Connected work/school accounts, token broker (AAD.BrokerPlugin) and the Credential Manager (all saved credentials, e.g. Git, RDP, services). The PC's domain or Azure AD membership and the local Windows account are not changed; they only appear as a note.

Module Development tools

Visual Studio (IdentityService), GitHub Copilot/CLI, VS Code accounts, Git (user.name/user.email, .git-credentials, Credential Manager), SSH keys and known_hosts, NuGet credentials/API keys and tokens in .npmrc/Yarn. Source code, repositories, extensions and the SSH config are kept.

Module Optional programs

Only if present: device2cloud/machinetoservice, Sophos Connect, eWON eCatcher (user data and access). Plus license notes (e.g. Siemens Automation License Manager): machine-bound licenses are not changed, only reported.

Module Traces

Temp, recycle bin, “recent items” (including jump lists and input history), RDP history, PowerShell history (PSReadLine) and the event logs of the whole PC. Very fresh temp files (under 60 seconds) and locked files are skipped.

4. Clean and verification run

After confirmation the selected categories are deleted. The log (below and as a file in the log folder) lists only categories and counts – never passwords or tokens in clear text; error messages are filtered as well.

Then the verification run analyzes the selected categories again. It must report “clean”. If not, it lists what was still found (common cause: a program is still running or wrote data again when it ended).

Edge: To prevent Edge from signing in again automatically, accounts in Windows (Settings › Accounts › Access work or school) must be removed too. The “Windows accounts” module removes connected accounts; the PC's Azure AD/domain membership is deliberately left unchanged and only reported as a note.

5. Secret scan (report only)

Searches the user profile and the extra folders from the settings for files containing credentials: Git remotes with a token in the URL, .git-credentials, .env, .pfx/.p12 and private keys, passwords in appsettings.json/secrets.json. The scan deletes nothing and never shows the value of a secret, only path and kind. Please fix findings by hand (e.g. revoke the token, remove the file).

6. Finish (optional)

  • Change computer name: takes effect after restart.
  • Sysprep: generalize /oobe /shutdown – removes the computer SID and shuts down. Cannot be undone; use deliberately.
  • Shut down: in 10 seconds.

The Windows account (password, sign-in) is never changed.

Settings

Language: German or English, effective immediately. Additional scan folders: one folder per line for the secret scan (e.g. where repositories live). Update check: asks GitHub for the latest version at startup at most every 20 hours. No usage data is transmitted; there is no telemetry.

Own modules

Modules are readable PowerShell scripts in the modules folder next to the program (one script per module, functions Analyze and Clean, JSON output). A new file is enough – no recompiling. Without UI: powershell -File modules\Browser.ps1 -Action Analyze. Details: CONTRIBUTING.md in the repository.

Troubleshooting

  • “Cleaning is blocked”: a check is red. Read the message in section 1 (no VM, no administrator, wrong profile).
  • Verification “not clean”: close programs, analyze again and clean. Error lines in the log show locked files.
  • “count unknown”: the SQLite file could not be read; cleaning still works.
  • No modules visible: the modules folder next to the .exe is missing or a script is broken (error text above the list).

What the tool deliberately does not touch

  • The Windows account: password, sign-in, account type, groups.
  • Installed programs and extensions, general browser settings, bookmarks (unless explicitly selected).
  • Documents, source code and repositories; server mailboxes; OneDrive files (only the connection is unlinked).
  • Anything outside the signed-in user's profile.

Full list: docs/NOT-TOUCHED.md in the repository.

Files and folders

  • Settings: %APPDATA%\DevVM-Cleanup\settings.json (Help › Open settings folder)
  • Logs: %APPDATA%\DevVM-Cleanup\logs\ (Help › Open log folder)
  • Modules: modules folder next to the program
  • No network access except the optional update check.
